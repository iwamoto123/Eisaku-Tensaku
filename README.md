# 英作文添削メーカー（第1段階）

生徒が提出した英作文の答案画像をアップロードすると、白谷塾の体裁で添削フィードバック資料を作り、
PDF または PNG として書き出すWebアプリです。

## できること

1. 答案の画像をアップロード（複数枚可・ドラッグ＆ドロップ・Cmd+V での貼り付けに対応）
2. 生徒名・級・担当講師・日付・出題内容を入力
3. **指摘したい英語の内容** を書くと、その項目は必ず資料で扱われる
4. **追加で伝えたいこと** を書くと、その内容が資料に反映される
5. Claude が答案を読み取り、添削フィードバック資料を生成（進行状況を段階表示）
6. 画面上で本文を直接編集（自動保存あり）
7. PDF または PNG で書き出し

## 起動のしかた

```bash
cd writing-tensaku
npm install
npm run dev
```

ブラウザで http://localhost:3210 を開きます。

`.env.local` に Anthropic の API キーが必要です。`.env.local.example` をコピーして使ってください。
（このリポジトリでは `task-notifier/.env` と同じキーをすでに設定済みです）

## 使い方

左のパネルに答案の画像と生徒の情報を入れて「添削資料をつくる」を押します。

生成には **2〜5分** かかります。進行状況はパネル下部にバーで表示され、
「答案を読み取っています」→「できている点を整理しています」→「直すところを書いています（3件目）」
のように、いま何を書いているかが分かります。

できあがったら、右側に資料が表示されます。

### 2つの自由記述欄の使い分け

**指摘したい英語の内容** … 講師が赤ペンを入れた箇所を書きます。ここに書いた項目は必ず資料で扱われます。
書き方は簡単で構いません。資料の水準に合わせて、原因・見分け方・書くときの合図まで展開されます。

```
・convenience → convenient（品詞の使い分け）
・文頭の Because の使い方
・hasn't ではなく doesn't have
・結論が1文目のコピーになっている
```

空欄にすると、AIが答案を読んで自分で優先順位をつけます。

**追加で伝えたいこと** … 英語の指摘以外で資料に入れたいことを書きます。

```
・前回と同じミスが続いているので重点的に扱ってほしい
・今は単語と熟語を優先する方針で進めている
・保護者からの質問に答える形で一言入れてほしい
・インデントの話は今回は省いてよい
```

資料の項目に馴染む内容ならその中に織り込まれ、独立した話題なら専用の見出しが立ちます。

### 編集と保存

「本文を編集する」を押すと、資料の文章を直接クリックして書き換えられます。
編集中は「編集内容を保存」「保存して編集を終える」の2つのボタンが出ます。

ツールバーの右に保存の状態が出ます。

- **未保存の変更があります**（オレンジ色）… まだ保存されていません
- **14:32 に保存しました** … 保存済みです

書き換えてから1.5秒経つと自動でも保存されますが、確実に保存したいときはボタンを押してください。

保存先はブラウザのローカルストレージです。ページを閉じて開き直すと
「前回の編集内容が残っています」という案内が出るので、復元するか破棄するかを選べます。
新しく資料を生成すると、前の下書きは消えます。

保存されるのは **1件分だけ** です。複数の生徒を並行して編集することはできません。

### 書き出し

| ボタン | 用途 |
|---|---|
| PDFで保存 | A4縦のPDF。保護者へメール送付、印刷して渡す場合はこちら |
| PNGで保存（ページ分割） | 見出しの切れ目でページを分けたPNG。LINEで送るならこちら |
| PNGで保存（1枚） | 縦長の1枚画像 |

ファイル名は `2026-08-16_yamada-hanako_writing-feedback.pdf` のような形になります。
「ファイル名」欄には英数字だけを入れてください（日本語ファイル名だとリンクが開けなくなるため）。

資料は内容が濃いぶん縦に長く、実測でA4換算16ページ前後、PDFで約5MBになります。
PNGのページ分割は10枚前後です。分量が多いと感じたら、編集モードで不要な項目を削ってから書き出してください。

「PNGで保存（1枚）」は資料が長いとブラウザのcanvas上限（16,384px）に当たるため、
自動で解像度を落として1枚に収めます。読みやすさを優先するならPDFかページ分割を使ってください。

## 技術スタック

| 層 | 使っているもの |
|---|---|
| フレームワーク | Next.js 16（App Router）／React 19／TypeScript |
| AI | Anthropic API（`claude-opus-5`、画像入力＋Structured Outputs＋ストリーミング） |
| PDF生成 | jsPDF（ブラウザ側） |
| PNG生成 | html-to-image（ブラウザ側） |
| スタイル | 素のCSS（`src/app/globals.css`）。CSSフレームワークは使っていません |
| データベース | なし |

サーバー側の処理は `/api/correct` の1本だけです。ここが Anthropic API を呼び、
返ってきたJSONをそのままブラウザへ流します。PDFとPNGの生成はすべてブラウザの中で完結します。

## データの保存場所

| データ | どこにあるか | 消えるタイミング |
|---|---|---|
| APIキー | `.env.local`（このPCの中のみ） | 手で消すまで |
| 答案の画像 | ブラウザのメモリ。サーバーには保存しない | ページを閉じたとき |
| 生成された資料 | ブラウザのメモリ | ページを閉じたとき |
| 編集した下書き | ブラウザのローカルストレージ（1件分） | 新規生成、または「破棄する」 |
| 担当講師名・級 | ブラウザのローカルストレージ | ブラウザのデータを消すまで |
| 書き出したPDF・PNG | ダウンロードフォルダ | 手で消すまで |
| API利用量の記録 | `../api-cost-notifier/data/` | 手で消すまで |

**データベースもサーバー保存もありません。** 生成履歴を残す仕組みは第2段階の課題です。

1件生成するごとに、使ったトークン数を `../api-cost-notifier/data/` に追記しています（生徒の情報は含みません）。
これは月次のAPI利用料をSlackへ報告するためのもので、`works/api-cost-notifier` が集計します。

答案の画像とプロンプトは Anthropic の API に送られます。API経由のデータはモデルの学習には使われません。
生徒の氏名を入れる欄があるので、その点は認識しておいてください。氏名を空欄にしても資料は作れます。

## スマホで使えるか

**閲覧はできます。生成と書き出しはPC推奨です。**

- 画面のレイアウトはスマホ幅に対応しています。表は横スクロールで読めます
- 画像のアップロードと生成は、スマホのブラウザでも動きます
- ただし **PDF・PNGの書き出しはメモリを大量に使う**ため（1万px超の画像を扱います）、
  スマホのブラウザでは失敗するか、極端に遅くなる可能性があります
- 本文の編集は、contentEditable の操作性の問題でスマホだと扱いにくいです

iPad（Safari）なら実用範囲だと思いますが、実機での確認はしていません。
現状は「PCで作って書き出し、できたPDF/PNGをスマホから送る」という使い方を想定しています。

なお今はローカル起動のため、同じPCからしかアクセスできません。
同じWi-Fi内のスマホから見たい場合は `npm run dev -- -H 0.0.0.0` で起動し、
PCのIPアドレス（例 `http://192.168.1.10:3210`）を開いてください。

## プロジェクトの管理方法

このディレクトリ単体がGitリポジトリです。

```
git@github.com:iwamoto123/Eisaku-Tensaku.git
```

変更を反映するときは次のようにします。

```bash
cd writing-tensaku
git add -A
git commit -m "何を変えたか"
git push
```

`.gitignore` で `.env.local`（APIキー）と `public/sample-output.json`（生徒名を含む生成結果）は
コミット対象から外してあります。**APIキーは絶対にコミットしないでください。**
新しく設定ファイルを足すときは、`.gitignore` に入っているかを先に確認してください。

`works` の他のツール（task-notifier など）はこのリポジトリには含まれません。別管理です。

### ファイルの役割

| 変えたいもの | 見る場所 |
|---|---|
| 添削の深さ・文体・切り口 | `src/lib/prompt.ts` の `SYSTEM_PROMPT` |
| 資料の構成（どの項目をどの順で出すか） | `src/lib/schema.ts` の `FEEDBACK_SCHEMA` |
| 見た目（色・余白・表組み） | `src/app/globals.css` の `.doc` 以下 |
| 項目の並びと組み立て | `src/components/FeedbackDoc.tsx` |
| ページ分割の高さ・解像度 | `src/lib/render-pages.ts` |
| PDF・PNGの書き出し | `src/lib/download.ts` |
| 進行状況の段階表示 | `src/lib/progress.ts` |
| APIの呼び出し | `src/app/api/correct/route.ts` |

`SYSTEM_PROMPT` には「指摘1つにつき表を1〜2個使って知識を体系化する」「ダッシュと体言止めを使わない」
といった、これまでのPDFの作り方を書いてあります。全講師の出力が変わる場所なので、変更は慎重に行ってください。

なお `FEEDBACK_SCHEMA` には項目の説明文を書きません。スキーマが大きくなりすぎると
API が `compiled grammar is too large` で弾くためです。説明は `SYSTEM_PROMPT` 側にまとめています。

### デザインを調整したいとき

http://localhost:3210/preview を開くと、`public/sample-output.json` を読み込んで
資料だけを表示します。APIを叩かずに見た目とPDF・PNG書き出しを試せます。

`?autotest=1` を付けると、資料の途中の1ページを実際にPNG化して画面に出し、
ページ数・寸法・PDFのサイズを表示します。分割位置や解像度を確認したいときに使ってください。

## うまくいかないとき

生成が途中で止まった場合、画面にエラーが出ます。よくある原因は次のとおりです。

| エラーの表示 | 原因と対処 |
|---|---|
| クレジット残高が不足しています | Anthropic APIの残高切れです。console.anthropic.com の Plans & Billing でクレジットを追加してください |
| レート制限に達しました | 短時間に投げすぎです。1分ほど待ってください |
| 出力の上限に達して途中で切れました | `.env.local` の `ANTHROPIC_MAX_TOKENS` を増やしてください（既定64000） |
| 生成が途中で終わりました（〜のところまで） | 通信が切れています。もう一度お試しください |
| 資料が途中までしか作られませんでした | 表示されている内容は不完全です。作り直してください |

より詳しい原因（停止理由とトークン数）は、`npm run dev` を実行しているターミナルに
`[correct] stop_reason=... input=... output=...` として出ます。

## コスト

1件あたりおよそ15〜20円です（claude-opus-5、答案画像1枚の場合）。
速さを優先したい場合は `.env.local` の `ANTHROPIC_EFFORT` を `medium` に下げてください。

## 第1段階の割り切り

- ログインなし。ローカルで自分だけが使う想定です。
- 生成履歴は残りません。編集中の下書きが1件分だけローカルに残ります。
- 講師ごとのカスタマイズ設定はまだありません（担当講師名と級だけブラウザに記憶します）。
- 生徒ごとの過去の答案との自動比較はできません。前回のミスを踏まえたい場合は
  「追加で伝えたいこと」に書いてください。

第2段階でログイン・講師設定・履歴を足す想定です。

## 他の講師に配るとき

現状はローカル起動なので、配るにはデプロイが必要です。Vercel にそのまま載ります。

関数の実行時間の上限は Hobby が300秒、Pro が800秒です（2026-07時点）。
生成の実測は約250秒なので Hobby でも動く可能性はありますが、余裕がありません。
答案が長い回や混雑時に超えるおそれがあるため、配布するなら Pro を推奨します。

もう1点、Vercelのリクエストボディは4.5MBが上限です。今は画像をbase64でJSONに入れて送っているので、
複数枚アップロードすると超える可能性があります。デプロイ時は画像をストレージに先に上げて、
URLで渡す形に変える必要があります。

APIキーをサーバー側に置くことになるので、あわせてログインの仕組みも必要になります。
